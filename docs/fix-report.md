# 2026-11-13 修复交付说明

本次修复基于 `main` 的 `82f2db8dca3d9e4d0cf2a02acb8d5a4f2398c435`，位于 `codex/ship-fixes`。范围是前两次审查确认的功能接线、记录完整性与安装启动问题。未合并原有 DIY 角色分支，也未发布正式版本。

## 改了什么

| 原来遇到的问题 | 本次处理 |
| --- | --- |
| DSH 换角色只是换人设，仍使用原来的会话和模型 | 每个项目保存各角色的模型与房间；先选择目标模型、打开目标会话，再提交交接任务。失败会提示，不显示假成功。 |
| 给未上场角色选模型，会改到当前角色 | 按角色单独保存；只有修改当前角色时才切换当前会话的模型。 |
| 代码变更、撤回、提交按钮没有接上 | 三项操作已连接实际 Git 操作，并通过 DSH 的登录保护接口访问。 |
| 清理记忆删掉回看记录，又虚报释放空间 | 调用执行器的实际整理能力；保留回看记录；没有统计时显示等待统计，不再编造百分比。 |
| 工作中换角色、模型或项目，会串到上一位角色 | 工作期间和启动切换期间拒绝这些修改，界面也禁用角色切换；请先完成任务或喊停。 |
| DSH 插话一直显示排队，失败也无反馈 | 区分排队、已提交、已被模型读取和提交失败。 |
| AI 边解释边使用工具时，回看漏掉解释 | 保留这类混合消息中的文字。 |
| 两个审批相互覆盖 | 改为排队；处理一项只移除对应项。 |
| 打包后的路径无法被外部 DSH 读取 | 使用真实磁盘目录，避免把归档路径用作工作目录或插件位置。 |
| 新用户运行 `npm run dsh` 缺少初始化 | 命令行与桌面入口共用初始化逻辑；支持迁移后的失效链接恢复。 |
| 找不到 nvm/fnm 安装的 Node 或 DSH | 补齐常用安装位置发现，并尊重用户指定的可执行文件路径。 |
| 打包工具版本不固定、生产启动依赖不完整 | 锁定 electron-builder；补齐构建依赖；生产入口使用预构建服务端；正确归类服务端运行依赖。 |
| 旧版 DSH 资源入口不兼容 | 同时保留两种资源处理入口；本机新版宿主已通过图片、音效与全新配置启动检查。 |

另外，测试暴露出服务端在 DSH 任务结束后没有同步恢复空闲状态，导致后续操作被误拦截；本次已修正。

## 仍需明确的能力和发布边界

- 当前 Codex CLI 适配器不支持手动整理上下文，会明确提示并保留历史。DSH 使用原生整理命令；直连对话使用本地摘录摘要，会丢失部分细节，原始回看记录仍保留。
- 每位角色需选择自己已配置的可用模型；角色名称不会自动提供相应厂商的账号或凭证。
- 新增角色房间及 Git 操作需要宿主支持受保护请求接口。本次验证版本为 DSH `0.2.2-rc.1`；旧版素材能显示，不代表新增操作接口也能使用。
- 桌面程序仍依赖本机已安装的 DSH。正式对外分发前，仍需处理 Apple 签名、公证和新机器安装验收。
- 角色、美术、Live2D 和音效的商业使用授权，无法通过改代码解决。本次没有擅自添加许可证，也没有声称已取得商业授权。详见 [发布说明](release-readiness.md)。

首次全量测试曾有 1 项失败，定位后修正任务结束状态，并重新执行服务端全量测试得到 50/50；没有隐去这一过程。
