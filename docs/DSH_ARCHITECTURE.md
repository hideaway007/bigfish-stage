# 架构定稿：基于 DeepSeek Harness (DSH) 的 P5 舞台方案

> 核心原则：**底层不造轮子，直接以 DeepSeek Harness (DSH) 作为唯一 Agent 内核；现有前端保留为 Demo 与 P5 舞台外壳；当前阶段优先围绕外围配置生成与补齐全部角色素材，不盲目大改主干代码。**

---

## 一、 为什么要从「后端调 CLI」切换为「DeepSeek Harness 底座」

1. **不再重复造后端轮子**：
   - 传统方案在自建 Node 服务里 `spawn` 外部 CLI 子进程、手写 JSONL 解析、手写 `git diff` 兜底、手写会话存储与设置面板，既繁琐又容易与原客户端配置割裂。
   - **DeepSeek Harness (`@deepseek-ai/dsh` / Cordis)** 本身就是「万物皆插件」的白盒 Agent 框架，原生自带完整的 Agent Loop（`followup` 发送与运行中插话、`cancel` 打断）、工具执行管线（`tools/pre-execute` 审批拦截与 `presentResult` 结构化 Diff）、多协议模型路由（OpenAI / Responses / Anthropic）以及会话持久化（`@deepseek-ai/dsh-session`）。
2. **人设与技术底座完全合一**：
   - 项目头号看板娘正是 **大肥鱼（DeepSeek V4 Pro）挥舞 Harness 娘**，以 DeepSeek Harness 作为真实底座、把原版界面重塑为 P5 红黑斜切舞台，产品叙事与底层架构完全闭环。
3. **现有前端保留为 Demo + P5 舞台主视图**：
   - 现有的 `src/stage/` 与 `src/demo/` 作为完整的 **Demo 演示舞台** 与 **P5 视觉组件库** 原样保留；底层通过轻量桥接层与 DSH 对接。

## 三、 当前阶段行动准则：先生成素材与外围配置，不改坏现有主干

为了避免两个人同时改同一批代码产生冲突，当前推进遵循以下节奏：

1. **【给双方 AI Agent 的硬性指令】严禁直接修改或推送 `main` 分支**：
   - **A 侧 AI（界面/交互/文案）**：必须从 `main` 拉取自己的独立分支（如 `agent-a` 或 `ui/<功能名>`），只在自己的分支上提交和推送。
   - **B 侧 AI（素材/外围配置/DSH 底座）**：必须从 `main` 拉取自己的独立分支（如 `agent-b` 或 `art/<功能名>`、`core/<功能名>`），只在自己的分支上提交和推送。
   - 双方一律通过各自独立分支 + PR 协同，严禁任何一方直接 push `main`，严禁跨界修改对方归属目录。
2. **不动现有可跑通的主干代码**：`src/stage/` 现有 Demo 与交互逻辑保持稳定可运行。
3. **围绕外围配置先行生产素材**：
   - 按《`docs/AI娘人设整理_配图版.pdf`》设定，先围绕 `public/characters/<id>/` 生成并替换四位角色的正式立绘（6 种表情 + 头像）、Live2D 拆件资源与角色包配置。
   - 准备好 DSH 外围配置模板（角色 ↔ 默认模型路由、插件挂载声明、舞台音效文件）。
4. **严格按 `docs/COLLAB.md` 的双人无重叠清单分工推进**。
